# Shorts Blocker 1.1: план и спецификация

## Проблема
Статус показывает «✅ Блокировка работает», но Shorts открываются откуда угодно (вкладка, лента или поиск, ссылка),
Reels в Instagram тоже не закрываются. Сломались оба приложения сразу, поэтому причин может быть несколько:

| # | Гипотеза | Как проверяем | Что делаем |
|---|----------|---------------|------------|
| H1 | YouTube и Instagram переименовали id плеера | диагностический дамп экрана | обновить id и добавить совпадение по префиксу семейства |
| H2 | Служба числится включённой, но не запущена (система её убила или «заморозила») | метка `onServiceConnected` и время последнего события | показывать на главном экране реальное состояние, а не только настройку |
| H3 | `getRootInActiveWindow()` возвращает не то окно (системная панель, клавиатура, PiP, всплывающее окно) | дамп со списком окон | перебирать `getWindows()` и проверять окна отслеживаемых приложений |
| H4 | Плеер рисуется без id (Litho/Compose) | дамп | резервные признаки: выбранная вкладка «Shorts» / «Reels» по тексту и описанию |

Статус «✅» сейчас проверяет только строку в настройках. Это само по себе ошибка (H2), её исправляем в любом случае.

## Что меняется

### 1. Детектор работает с деревом экрана, а не с поиском по id
- `core/ScreenNode`: абстракция узла (id, класс, текст, описание, видимость, «выбран», дети). В Android её реализует обёртка над `AccessibilityNodeInfo`, в тестах — фейковое дерево.
- `ShortFormDetector.decide(pkg, root)` → `Decision{action, reason}`. В `reason` записывается, какой признак сработал (для диагностики).
- Правила:
  - TikTok (4 пакета) → `HOME`, дерево не обходится.
  - YouTube и ReVanced: `BACK`, если виден узел с id из семейств плеера Shorts. Это точные имена и префиксы `reel_recycler`, `reel_player`, `reel_watch`, `shorts_player`, `shorts_container`, а префикс ресурса — пакет приложения или оригинального YouTube. **Не блокируются**: `reel_shelf*`, `reel_item*` (полка и миниатюры в ленте), обычный плеер `watch_player`.
  - YouTube, резервный признак: выбранный (`selected`) узел с текстом или описанием, равным «Shorts» без учёта регистра и пробелов → `BACK`.
  - Instagram: `BACK`, если виден узел с id, начинающимся с `clips_viewer` (префикс `com.instagram.android`). Резервный признак: выбранная вкладка «Reels». **Не блокируются**: `clips_tab` (кнопка в меню), лента, сторис.
  - Невидимые узлы и всё под ними игнорируются. `null`-дети пропускаются.
- Обход итеративный (без рекурсии), не больше 3000 узлов, чтобы не тормозить телефон. Если лимит превышен, возвращается `NONE`, если признак до этого не найден.

### 2. Выбор окна (H3)
- `core/WindowPicker.pick(List<WindowInfo>)` → окна для проверки по порядку: только окна приложений (`TYPE_APPLICATION`) отслеживаемых пакетов, сначала активное или в фокусе, затем остальные. Системная панель, клавиатура и сам Shorts Blocker пропускаются.
- В `accessibility_config.xml` добавляется `flagRetrieveInteractiveWindows` и событие `typeWindowsChanged`.

### 3. Реальное состояние службы (H2)
- Служба пишет в настройки: `connectedAt` (в `onServiceConnected`), `lastEventAt` (последнее событие от отслеживаемого приложения), `lastBlockAt` и `lastBlockReason`. Запись не чаще раза в 5 с.
- `core/ServiceHealth.evaluate(inSettings, switchOn, connectedAt, now)` → `OFF` / `PAUSED` / `NOT_RUNNING` / `OK`.
  `NOT_RUNNING` означает, что служба включена в настройках, но не подключилась. Экран подсказывает выключить и снова включить её и отключить экономию батареи.
- `core/Ago.format(ms)` → «только что», «12 с назад», «5 мин назад», «3 ч назад», «2 дн назад».
- Главный экран: статус, «последнее событие из YouTube/Instagram: …», «последняя блокировка: … (признак)».

### 4. Режим диагностики (H1, H4)
- Кнопка «Диагностика»: блокировка ставится на паузу на 2 минуты, служба записывает дерево каждого нового экрана YouTube и Instagram и список окон.
- `core/ScreenDump.dump(pkg, root, maxNodes)` → текст: одна строка на узел, отступ по глубине, `id`, короткий класс, `desc`, `text` (до 40 символов, переводы строк экранированы), метки `[sel]`, `[hidden]`; в конце `… обрезано`, если сработал лимит.
- `core/DumpLog` — кольцевой буфер: не больше 20 экранов и 200 КБ, подряд идущие одинаковые дампы не дублируются.
- Кнопка «Отправить отчёт» → `ACTION_SEND` (Telegram, почта). Отчёт содержит версию приложения, версии YouTube и Instagram, модель телефона и Android, дампы. Интернет-разрешения по-прежнему нет. Текст с экрана попадает в отчёт только в режиме диагностики и только по нажатию.

### 5. Репозиторий и сборка
- Код в `github.com/Anton-Onskul/shorts_blocker`. Ключ подписи **не коммитится** (`signing/` в `.gitignore`): пароль от него опубликован в README, а с ключом кто угодно соберёт «обновление».
- GitHub Actions: на каждый push — `./run_tests.sh`; на тег `v*` — сборка `build_apk.sh`, подпись ключом из Secrets (`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`), APK в Releases. Ключ тот же, что у v1.0, поэтому APK встаёт поверх старой версии.

## Чего тесты не покрывают
Реальные id в текущих версиях YouTube и Instagram — их даст только дамп с телефона. Работа Android API (`getWindows`, убийство службы системой) проверяется вручную на устройстве.
